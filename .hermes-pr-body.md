## BOOTSTRAP DESIGN

`BOOTSTRAP.md` is the single entry point. A new session reads exactly two files by default: `BOOTSTRAP.md` + `chat-orchestrator/SKILL.md`. Everything else is lazy-load via the registry table. Startup ritual and precedence are stated in the first 30 lines so even a minimal context budget gets them.

## SKILL REGISTRY

Exactly nine skills (`SKILLS.md`): chat-orchestrator, requirement-grill, agent-routing, model-routing, engineering-discipline, code-review, pr-delivery, project-hygiene, gui-acceptance. Registry extension requires a PR; no growth by accretion.

## LAZY LOADING

Orchestrator routes by signal table and loads at most a primary skill plus its named references. Chained phases (grill → route → implement → deliver → review) load each skill when reached. Never preload the whole repo into context.

## PRECEDENCE

Current explicit user instruction > current project Contracts/ADR/project skills > AI_chat_skill Global Skills > generic defaults. Global Skills can never override a frozen project rule; conflicts are noted back to this repo.

## REQUIREMENT GRILL

Fully de-projected version of the AI-Reveal skill: five layers (Goal → Workflow → Failure/Edge → Data/State/Lifecycle/Recovery → Acceptance), adaptive 3–6 question rounds, semantic trigger phrases, do-not-grill gate, DELEGATED/UNKNOWN recording, agent self-serves facts, Requirement Decision Sheet output with Ready for Planning YES/NO gating Architecture → Plan → Implementation.

## AGENT ROUTING

Seven roles defined independently of models (Product/Architecture Orchestrator, Implementation, UI/Browser, System/Backend, Research, Independent Reviewer/Red Team, Final Architecture Gate), plus an informational default mapping (ChatGPT → PM/Grill/Architecture/Final Gate; Claude → UI/Browser; Codex → System/Backend; Hermes/Ox → Research/Red Team/Review). Project ownership overrides defaults; contract/schema freezes require author ≠ reviewer.

## MODEL ROUTING

Luna = Max only (default); Terra = High/XHigh; Sol = High/XHigh/Max. Task classes: mechanical/tests/docs → Luna Max; ordinary cross-module/exploratory → Terra High; complex debug → Terra XHigh; Schema/Contract/Architecture/Migration/Concurrency/Lifecycle → Sol High; extreme blocker/final gate → Sol XHigh/Max. Hard rules: never default everything to Sol; must declare 模型：XXX　Reasoning：XXX to the user before starting any Codex task.

## PR DELIVERY

Full agent reports go into the PR description or top-level comment — never chat-only. Fixed acknowledgments: success `已写进 PR #XX，无需向 GPT 复述。`, failure `未写进 PR，需要向 GPT 转述。`. No fabricated verification; platform-blocked delivery is reported immediately.

## SELF TESTS

Ten scenarios in `tests/scenarios/README.md` covering grill/no-grill routing (1–2), model routing incl. mandatory declaration (3–5), PR delivery protocol (6), precedence conflict (7), GUI acceptance both branches (8–9), DELEGATED (10). All walked against V1 texts: PASS, no mechanical questionnaires, no undisclosed model choices, no self-reported visual verification.

## TOKEN / CONTEXT STRATEGY

Default context cost = BOOTSTRAP (~2 KB) + orchestrator (~1.8 KB). Every other skill costs zero until routed to. Skill bodies are single-file, reference-free where possible; long probe libraries were deliberately left out of V1 to keep load cost low. Registry capped at nine.

## RISKS / OPEN QUESTIONS

1. No enforcement layer: skills are guidance; drift is caught only by review. A future lint/sync check could be added if this repo grows consumers.
2. Default agent↔role mapping will age; it is marked informational and needs periodic re-validation.
3. Codex Luna/Terra/Sol effort tiers are convention-encoded; if upstream renames tiers, model-routing needs a versioned update.
4. GPT-side consumption currently assumes raw.githubusercontent.com fetch; a stable tag/release (v1.0) after merge would give sessions a pinned reference.
5. Whether project repos should vendor copies of these skills or always reference this repo live — open decision.
